# verify/ —— 团队验证记录

> 这个目录回答一个问题：**"这个版本的代码，谁在哪台机器上跑通了？"**

---

## 为什么需要它

三个人各自在自己机器上跑仿真。**`*_result.txt` 被 `.gitignore` 排除了**
（每次跑内容都变，提交上去全是无意义的冲突）。

但"**我跑通了，队友怎么知道**"这个需求是真实的 —— Git 本身解决不了。

**做法**：每次跑完 `run_tb.ps1`，自动生成一个报告文件放进这里。
**文件名里带【用户 + 机器 + commit】，所以三个人各生成各的，永远不会冲突。**

---

## 文件名规则

```
<用户>_<机器名>_<commit>[_dirty].md
```

| 例子 | 含义 |
|---|---|
| `忆洛_DESKTOP-A1B2_47a2f59.md` | 忆洛在 DESKTOP-A1B2 上，对 commit `47a2f59` 的验证 |
| `B_ThinkPad_47a2f59.md` | 队友 B 在 ThinkPad 上，**同一个 commit** 的独立验证 |
| `忆洛_DESKTOP-A1B2_47a2f59_dirty.md` | **有未提交改动** —— 这个结果不严格对应 `47a2f59` |

**注意 `_dirty` 后缀**：它表示"跑的时候工作区不干净"。
这种报告只能当参考，**不能当作"这个 commit 验证通过"的证据**。

---

## 怎么用

### 跑完仿真后提交

```powershell
cd sim
powershell -ExecutionPolicy Bypass -File toolchain\run_tb.ps1

# 脚本会提示你执行：
cd ..
git add verify/
git commit -m "验证: 47a2f59 PASS (8 tb / 271 checks)"
git push
```

### 看别人验证过什么

```powershell
git log --oneline verify/                    # 所有验证提交
git log --oneline -p verify/ | more          # 带内容
ls verify/                                   # 当前所有报告
```

### 拉最新代码时先看这个

```powershell
git pull
ls verify/ | sort                            # 队友有没有提交新报告？
```

**如果某个报告结论是 FAIL** —— 说明有人提交了没跑通的代码，
**在群里问一下，别直接在上面继续改。**

---

## ⚠️ 这个目录**不替代** Git 的验证纪律

| 手段 | 作用 |
|---|---|
| `verify/` 报告 | **记录**"谁验证过什么"（事后可见、可追溯） |
| 合并前自查 | **保证**"进 main 的都是跑通的" |

**两条都要有。** 只靠报告是"事后发现"，只靠自查是"没人知道"。

## 为什么不用共享对话来同步

我们讨论过一个方案：**三个人共用一个 AI 对话，把代码贴进去，互相看运行情况**。

**技术上不成立**（已实测）：

| 证据 | 含义 |
|---|---|
| 会话存在 `%USERPROFILE%\.dsh\sessions\` | **纯本机存储，不在云端** |
| 目录名按工作区绝对路径哈希分桶 | 队友用户名不同 → **完全是另一个桶** |
| `http://127.0.0.1:<端口>` 且端口每次变 | **本机回环** → 队友的机器连不上 |
| 源码里搜不到 `multiUser` / `shareSession` | **没有多用户实现** |

**即使能做，机制也是错的**：

1. **还是全量覆盖** —— 和压缩包一样，无法回答"谁改了哪一行"
2. **对话会被自动压缩** —— 上下文压缩**会丢细节**（比如"这个分支顺序为什么不能反"）
   三个人 30 天的代码上传会反复触发压缩，**仓库不会压缩，对话会**
3. **无法判断基线** —— 三个人贴同一文件的不同版本，没人知道哪个是当前版本
4. **凭证共享有安全风险** —— 一个账号三个人用

**结论**：

| 要同步的东西 | 手段 |
|---|---|
| **代码** | **Git** |
| **"谁验证过什么"** | **`verify/` 报告**（本目录） |
| **设计意图 / 踩过的坑** | **`doc/` 文档**（DSH 会话上下文不共享，必须落文档） |
| **临时讨论、求助** | 聊天群 —— 但**结论必须落进文档并提交** |
