# 后退修复（2026-11-01）

> 生产版 `arm/wifi_rc.py`（36220 字节）的【后退】按钮是**坏的**：
> 按下后退，小车会以 **100% 满速前进**。
> 这个文件是修好的版本，**没有动生产版**，等你验证通过再替换。

---

## 一、bug 是什么

`uart_proto.make_rc_cmd()` 内部有钳位：

```python
def make_rc_cmd(steer, speed, seq):
    sp = int(speed)
    if sp > 100:
        sp = 100          # ← 这里
```

而调用方按协议传的是 `(rev << 7) | mag`：

```
后退 40% 时：  rev=1, mag=40
           → speed_byte = 0x80 | 40 = 168
           → 168 > 100
           → 被钳成 100
           → bit7（后退标志）丢失
           → FPGA 收到的是【100% 前进】✗
```

### 实测证据

```
前进 40%：pack_frame  : aa 55 01 05 00 03 00 28 07 28 55 aa
          make_rc_cmd : aa 55 01 05 00 03 00 28 07 28 55 aa   ✓ 一致

后退 40%：pack_frame  : aa 55 01 05 00 03 00 a8 07 a8 55 aa   ✓ 正确
          make_rc_cmd : aa 55 01 05 00 03 00 64 07 64 55 aa   ✗ speed 被钳成 100
```

## 二、这一版怎么修的

### ① 后退走专用路径，自己组载荷

```python
if rev:
    _pl = bytes([steer & 0xFF, (0x80 | mag) & 0xFF, seq & 0xFF])
    uart.write(up.pack_frame(up.TYPE_RC_CMD, _pl))
else:
    uart.write(up.make_rc_cmd(steer, mag, seq))   # 前进/转向走验证过的老路
```

**没有改 `uart_proto.py`**（协议库改动风险大）✓
帧头 / 长度 / BCC / 帧尾仍然全部由 `pack_frame` 生成，协议实现只有一份 ✓

**前进/转向完全走原来的路径** ✓ —— 把改动范围压到最小 ✓

### ② 串口错误日志节流（上一版翻车的可能原因）

上一版（`wifi_rc_36657_revfix.py`）在发送失败时**每一帧都写 `/sdcard` 日志** ✗：

```
20Hz 发送 → 每秒 20 次 SD 卡写入 → 每次 10~50ms
    → 主循环被拖死 → HTTP 请求超时 → 页面打不开 ✗
```

**这一版改成每 2 秒才记一次** ✓ 而且只 `print`（不写卡）✓

> 注：上一版页面打不开的**确切原因尚未 100% 确认**（也可能是文件传输不完整）。
> 但"高频写卡"是最可疑的一环，这一版从根上去掉了。
