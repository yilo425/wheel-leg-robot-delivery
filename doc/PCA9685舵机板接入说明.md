## 1. 为什么用 PCA9685

原来舵机 PWM 由 `servo_lift` 硬件生成（最省事），但接线有个实际问题：

```
一个 FPGA 引脚要带 2 个舵机的信号输入
    ↓
GPIO0 是单孔母座 → 插不进两根线 ✗
    ↓
要么买 Y 线、要么自己焊分线板（你们没有焊接经验）
```

**PCA9685 一次解决**：
- 4 个舵机**直接插**（16 个 3P 插座，用 4 个）
- 电源走**螺丝端子**（免焊）
- 和 FPGA 只连 **4 根线**（VCC/GND/SDA/SCL）

## 2. 接线（全免焊）

### 2.1 逻辑侧（4 根杜邦线）

| PCA9685 | 接 FPGA | 孔位 | 说明 |
|---|---|---|---|
| `VCC` | **`3V3`**（UART 那边那个）| —— | ⚠️ **不能接 5V**，否则 I2C 电平变 5V 打死 FPGA |
| `GND` | `GND` | 顶排 6 | ★ 同时就是信号地参考 |
| `SDA` | `i2c_sda` = `D19` | **顶排 3** | 板上自带 10k 上拉，不用外加 |
| `SCL` | `i2c_scl` = `C20` | **顶排 4** | 同上 |

### 2.2 功率侧（螺丝端子，2 根粗线）

| PCA9685 | 接 |
|---|---|
| `V+` | 5~6V 降压输出的**红线**（剥 5mm，拧紧）|
| `V−` | 5~6V 降压输出的**黑线** |

> ★ 再从 `V−` 并一根细线到 **FPGA 的 GND**（单点参考）。
> **不要**让舵机的大电流走 FPGA 的 GND（会地弹 → 复位）。

### 2.3 舵机（直接插）

| 舵机 | PCA9685 通道 |
|---|---|
| 前腿 1 | **0** |
| 前腿 2 | **1** |
| 后腿 1 | **2** |
| 后腿 2 | **3** |

通道 0、1 听 `lift_cmd[0]`，通道 2、3 听 `lift_cmd[1]` ——
**同组两个舵机写同一个计数值，自然同步** ✓

## 3. 驱动做了什么（`rtl/driver/pca9685_drv.v`）

### 3.1 初始化序列（datasheet 要求）

| 步骤 | 寄存器 | 值 | 说明 |
|---|---|---|---|
| 1 | MODE1 (0x00) | `0x10` | SLEEP=1（必须先睡才能写 PRESCALE）|
| 2 | PRE_SCALE (0xFE) | **121** | `round(25MHz/(4096×50)) − 1` |
| 3 | MODE2 (0x01) | `0x04` | OUTDRV=1（推挽）|
| 4 | MODE1 (0x00) | `0x20` | AI=1（自动递增）+ 唤醒 |
| 5 | —— | 等 1ms | 振荡器起振，然后 `init_done=1` |

### 3.2 角度换算（刻意避开除法器）

```
50Hz → 周期 20ms → 4096 计数 = 20ms → 1 计数 ≈ 4.88us

count = 102 + height × 4

  height=0   → 102  (0.5ms)   舵机"放下"
  height=100 → 502  (2.45ms)  舵机"抬起"
```

**为什么是 ×4 而不是 ×4.1**：×4.1 要除法器；×4 只要移位。
代价是最大行程 2.45ms 而不是 2.5ms（差 2%，约 1.8°）——
**反而更安全**：不会顶着舵机的机械极限 ✓

`height` 来自 CONFIG 帧 `0x10`（`cfg_lift_height`，0~100，超过 100 被钳位）。

### 3.3 只在目标变化时写

PCA9685 会**自己保持**写进去的 PWM 值，不需要周期性刷新。

```
一轮全 4 通道更新 = 16 次单字节 I2C ≈ 5ms @100kHz
每 20ms 重写会把 I2C 占满 → 改成"只在变化时写"
```

### 3.4 和 `i2c_master` 的分工

**本模块只做 FSM，不例化 `i2c_master`** —— 这样 testbench 可以用一个
"命令记录器"替换总机，直接验证**寄存器序列和数值**；
I2C 的时序正确性已由 `i2c_master` 自己的 tb 覆盖，不重复验证。

## 4. ★ 还差什么：`top.v` 里的接线

**驱动本身已验证，但还没接进 `top.v`** —— 原因和步骤都写在这里。

### 4.1 为什么没接完

`top.v` 是 1400 行的关键文件，接续需要：
1. 加 `parameter integer SERVO_IF = 0`（0=直接PWM，1=PCA9685）
2. 加内部线 `pca_scl_i / pca_sda_i / pca_start / ...`（9 根）
3. 在 §1.5（TOF 那个 generate）里把 `assign i2c_scl = 1'bz` 改成
   `(SERVO_IF != 0) ? pca_scl_i : 1'bz`
4. 在 §4.6（`servo_lift` 之后）加一个 `generate`：
   例化 `i2c_master` + `pca9685_drv`，接到 `pca_scl_i/pca_sda_i`
5. 编译期断言：`SERVO_IF=1` 时必须 `TOF_IF=1` 且 `IMU_ENABLE=0`

第 3、4 步必须**放在正确的位置**：
- `assign i2c_scl` 在 §1.5（第 ~690 行）
- 但 `lift_cmd` / `cfg_lift_height` 在 §4~§5 才声明（第 ~1100 行）
- **Verilog-2001 先用后声明会生成隐式 1 位网** → 所以"选择"放 §1.5、"例化"放 §4.6

### 4.2 建议的接法（下一步照这个做）

```verilog
// ① 参数区（TOF_IF 附近）
parameter integer SERVO_IF          = 0,
parameter integer SERVO_I2C_SCL_HZ  = 100_000,
parameter integer SERVO_PWM_HZ      = 50,
parameter [6:0]   SERVO_PCA_ADDR    = 7'h40,
parameter integer SERVO_COUNT_MIN   = 102,
parameter integer SERVO_COUNT_PER_H = 4,

// ② 模块体开头（端口列表之后）声明
wire pca_scl_i, pca_sda_i;
wire        pca_start;
wire [6:0]  pca_dev_addr;
wire [7:0]  pca_wr_data;
wire        pca_reg_addr_en;
wire [7:0]  pca_reg_addr;
wire        pca_done, pca_ack_err, pca_init_done, pca_err_sticky;

// ③ §1.5 的 SR04 分支里，把两行 assign 换成
assign i2c_scl = (SERVO_IF != 0) ? pca_scl_i : 1'bz;
assign i2c_sda = (SERVO_IF != 0) ? pca_sda_i : 1'bz;

// ④ §4.6（servo_lift 之后）
generate if (SERVO_IF != 0) begin : g_servo_pca
    i2c_master #(...) u_servo_i2c (
        .scl(pca_scl_i), .sda(pca_sda_i), ... );
    pca9685_drv #(...) u_pca9685 (
        .lift_cmd(lift_cmd), .lift_height(cfg_lift_height), ... );
end endgenerate
```

> ⚠️ 改完必须跑：`check_decl_order.py`（它会抓"先用后声明"）、全量回归、综合。

## 6. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **V+ 走线只有 2~3A** | 4 个 MG996R 正常 2A、堵转 10A | ① 挡件调到"刚好顶住" ② 抬腿超时降级 ③ 板上 1000µF |
| **VCC 接 5V** | I2C 电平变 5V → 打死 FPGA | **只能接 3V3** |
| **地址冲突** | 默认 0x40 | 单块板没问题 |
| **板子没插时** | 每次写都 NACK | 驱动**不卡死**，`err_sticky` 记一笔继续跑 ✓ |

## §9 已修复（2026-10-25）

**根因**（和 §8 的猜测不同，不是 busy 握手问题）：

舵机分支的 `i2c_master` 原来接在**内部线**上：

```verilog
// 旧（错）
i2c_master u_servo_i2c ( .scl(pca_scl_i), .sda(pca_sda_i) );
assign i2c_scl = (SERVO_IF != 0) ? pca_scl_i : 1'bz;   // <- §1.5 分支 A / C
```

`assign pad = 内部线` 是**单向**的：引脚（`i2c_scl`）上的上拉**回不到** `pca_scl_i`。
于是主机读自己那根线永远是 `z` -> `scl_s2` 永远不是 1 ->
**卡在 `S_START` 的 step1**，一直等到 `TIMEOUT_MS`（默认 10ms）才退出。

实测现象：`drv_st=5 (S_WAIT)`、`i2c_state=1 (S_START)` 卡住约 8ms，
然后超时 -> `ack_err` -> 驱动继续走完剩下的初始化 -> `init_done` 晚了 8ms。

**修法**（和 TOF/IMU 分支保持一致）：

```verilog
// 新（对）
i2c_master u_servo_i2c ( .scl(i2c_scl), .sda(i2c_sda) );
// §1.5 分支 A / C 里那两条 assign 全部删掉（含 pca_scl_i/pca_sda_i 声明）
```

上拉、开漏、仲裁都不受影响：每根 I2C 线上只有一个 `i2c_master` 在驱动
（`SERVO_IF=1` 要求 `IMU_ENABLE=0`；`TOF_IF=1` 时 TOF 走 SR04 不上 I2C）。

2. `init_done` 升起那一刻**正好 4 次** I2C 事务
3. 从机侧读回：`MODE1` 先写 `0x10`、`PRE_SCALE=121`、`MODE2=0x04`、`MODE1` 最后 `0x20`
4. **ACK 正常**（`err_sticky=0`）、地址全对、`hold_err=0`（SCL 高电平期间 SDA 未变）
5. 抬腿 `lift_cmd=3, h=50` -> **16 次事务**，4 个通道 `OFF = 102+50*4 = 302`

> ★ 教训（值得记进 `doc/踩坑与经验.md`）：
> **开漏 inout 引脚不能用 `assign pad = internal;` 的方式"映射"** ——
> 那样上拉只在 pad 侧，内部读不到高电平。要么直接把模块接到 pad 上，
> 要么显式做 `assign internal_in = pad;` 的双向结构。
