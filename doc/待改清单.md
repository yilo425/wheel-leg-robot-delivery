## 1. 站立高度："0 状态"的腿不是垂直的（待改）

**记录时间**：2026-10-30 晚（组装后实测）

### 现象

| 状态 | 实测腿的角度（相对垂直方向）|
|---|---|
| **上电（0 状态 / 高位）** | **向外约 30°** |
| **按【降低】后** | **向外约 75°** |

**摆动量 = 75° − 30° = 45°** ✓ 和设计一致（`STANCE_CNT_SPAN = 102` 计数 ≈ 45°）✓

### 问题

**0 状态应该是"腿垂直"** ✗ 现在偏了 30° ✓

### 原因

`stance_ctrl` 的 `CNT_MID = 307`（对应 1.5ms 舵机中立位），
但**装配后**舵机中立位并不等于腿垂直 —— 机械安装角差了 30° ✓

### 改法（待实现）

给 `stance_ctrl` 加一个**装配补偿参数** `LEVEL_CNT`：

```verilog
// 30° ≈ 333us ≈ 68 个 PCA9685 计数（1 计数 ≈ 4.88us，45° ≈ 102 计数）
parameter integer LEVEL_CNT = 68,

// 前腿和后腿都"向外撇"，所以补偿方向相反
assign cnt_front = (CNT_MID - LEVEL_CNT) + pos;   // 注意 INVERT 的符号
assign cnt_rear  = (CNT_MID + LEVEL_CNT) - pos;
```

**补偿后预期**：
- 0 状态 → 腿垂直（0°）
- 降低 45° → 腿约 45°

### 需要确认的问题

| # | 问题 |
|---|---|
| 1 | **0 状态是否要"腿垂直"？**（还是保持现在的外撇 30°）|
| 2 | **降低后希望多少度？**（现在 75°，补偿后会是 45°）|
| 3 | 前腿和后腿的**外撇角度是否一样**？（如果不一样，要分别给前/后两组补偿）|
| 4 | **左右两侧是否对称**？（如果某侧偏更多，那是机械装配问题，要单独配）|

### 相关代码位置

| 文件 | 内容 |
|---|---|
| `rtl/app/stance_ctrl.v` | `CNT_MID` / `CNT_SPAN` / `INVERT` 参数，`cnt_front` / `cnt_rear` |
| `rtl/top.v` | `STANCE_CNT_MID` / `STANCE_CNT_SPAN` / `STANCE_INVERT`，`u_stance` 实例 |

## 3. 轮距实测 230mm（2026-11-01）

| 参数 | 值 |
|---|---|
| **轮距 W** | **230mm**（左右轮着地点中心距）|
| 轮径 D | 48mm |
| 40% 时实测速度 | 502.7 mm/s（0.6s 转 2 圈）|
| **90° 转弯时间 TURN_MS** | **360ms**（T = W·π/2 ÷ 2v = 361.3÷1005.4）|

**转弯时的扫掠半径**（绕内侧轮转）：
```
车身长 242、宽 230，R=W/2=115
外侧前角扫掠半径 ≈ √((115+115)² + (121)²) ≈ 262mm
→ 原地转 90° 需要周围约 30cm 净空
```

**标定方法**：
```
地上画直角（或用两块砖摆 90°）
发一次左右转，看车头偏差
每偏差 2.5° 就调 TURN_MS 10ms（偏大调小、偏小调大）
```

## 4. ★★ 腿的电机安装孔要改（2026-11-01 实测发现）

### 问题

```
mech/leg_70mm.scad 的电机安装孔是 12mm × 12mm 四孔方阵：

  ●─────●   相邻孔距 12mm  ← 用户拧了这两个 → 电机被压歪 → 轴抱死 ✗
  │     │
  ●─────●   对角孔距 17mm  ← 应该用这两个 ✓
```

**实测**：只上 1 颗螺丝能转；上 2 颗相邻孔螺丝完全锁死 ✗

### 后果（链条）

```
相邻孔拧死 → 电机变形 → 输出轴抱死 → 轮子转不动
    → 发运动指令 → 电机堵转（2~3A）
    → TB6612（额定 1.2A，无过流保护）过热击穿 ✗
    → 这就是 C 通道烧毁最可能的真实原因
```

### ✅ 结论：**模型不用改**（2026-11-01 用户实测）

```
沉槽（CBORE）起作用了：
  螺丝头沉进腿里 → 拧紧后螺丝头不露出 → 不再顶到/压歪电机壳体
  → 两颗螺丝拧死也完全顺滑、非常稳固 ✓
```

**之前的"锁死"是螺丝头没沉进去导致的** ✓ 不是孔距问题 ✓
**模型保持现状即可** ✓

> ⚠️ 唯一要注意：螺丝必须拧到**沉进沉槽**，别露头


### 临时对策（今晚用）

```
用【对角】两个孔（17mm）
或者 1 颗螺丝 + 2 根扎带（模型已有扎带孔：x=30/44，y=±7）
```

## 5. ★★ 2026-11-02 实机发现的问题（先记录，不急改）

### 5.1 【必修】D 通道速度不受控，永远按高速转

```
现象：手机点【前进 40%】→ A/B/C 按 40% 转，但 D 通道按 80% 左右的高速转
      而且这个问题"几天前就有"，不是今天接线导致的
```

**根因分析**：
```
固件的速度控制是【闭环】的：
  VREF_FULL = 69 = "满速目标计数/窗口"（编码器计数）
  motion_decision 输出 target（目标计数）
  → 速度环根据【编码器反馈】算占空比
        ↓
  但编码器【没接】✗
  → 编码器引脚（PULL_MODE=UP）恒为高
  → 速度环永远认为"速度为 0"
  → 积分饱和 → 占空比顶到最大 → 永远高速 ✗✓
```

**两个解决方案**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 接编码器** ★★★ | 4 个电机 × 2 根 = 8 根线，接 FPGA 的 E1A/E1B…E4A/E4B | 8 根线，但是**正确解法** ✓ |
| **B. 加开环模式** | RTL 加参数 `OPEN_LOOP=1`：duty = speed_pct × DUTY_GAIN / 100，不用编码器 | 改 RTL + 重烧，但不用接线 ✓ |

**方案 B 的改法**（如果做）：
```verilog
// motion_decision 里：
//   现在是 target = base（编码器计数目标），交给速度环
//   开环模式改为直接输出 duty = speed_pct × 128 / 100
```

> ⚠️ 用户说"如果要动 ARM 的 WiFi 模块就不改了" —— 这个改动在 **RTL（FPGA）**，
> **不涉及 ARM** ✓ 所以可以做 ✓

### 5.2 转向时前后轮反向

```
现象：点【右转】→ 后两个轮正转，前两个轮反转
      点【左转】→ 相反
```

**分析**：
- 正常差速转向：同侧同向、异侧反向 ✓
- 现在"前正后反" = **同侧的前后轮方向相反** ✗
- 可能是接线（前后腿镜像安装）或 `DIR_INV_MASK` 的分组不对

**待定**：等接线稳定后，用逐通道测试确认每个通道的物理位置和方向，再定 `DIR_INV_MASK`

### 5.3 通道 ↔ 车轮的对应关系（每次接线都会变）

```
用户反馈：每次重新接线，孔位对应的前后左右都会变
    ↓
原因：接线时哪个电机插哪个座是随机的
    ↓
对策：接线后必须【逐通道测试】重新确认，然后调整：
   · STEER_COEF（左轮+1 / 右轮-1）
   · DIR_INV_MASK（方向取反）
```

**建议**：在接线表上给每根线贴标签（A/B/C/D + 左前/右前/左后/右后）✓ 避免每次重认
