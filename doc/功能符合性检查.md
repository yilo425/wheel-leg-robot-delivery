# 功能符合性检查（需求 vs 现有代码）

> 版本：v1.0　日期：2026-10-13
> 编写：A（FPGA）
> **本文档只做审计，不改代码。**
>
> 背景：三个人重新核对了整车运行逻辑，修正了一个关键误解 ——
> **轮子在腿的末端**，腿大部分时间蜷缩，只负责把**车身**顶起来处理障碍。
> 本文档逐项核对现有 RTL 能否实现新的功能定义。

---

## 0. 需求原文（三个人核对后的版本）

| 障碍类型 | 例子 | 策略 |
|---|---|---|
| **① 正常行驶** | 无障碍 | 靠轮子走，腿蜷缩 |
| **② 低矮小障碍** | 小石头，**长度 < 整车** | **四条腿抬升** → 直接开过去（防主体磕碰）|
| **③ 大障碍** | 长度 **≫ 整车** | 抬腿无用 → **绕过避障** |
| **④ 台阶/门槛** | — | **两腿抬升**，慢慢跨过 |

## 1. 逐项审计

### ✅ ① 正常轮式移动 —— **能实现**

**代码位置**：`main_fsm.v` 的 `S_AUTO` 状态

```verilog
S_AUTO: begin
    if (obst_stop || vis_obst)  nstate = S_AVOID;
    else if (low_obst)          nstate = S_LIFT;
    else if (goal_reached)      nstate = S_GOAL;
    // 否则保持 S_AUTO
end
```

**输出**（`S_AUTO` 段）：`lift_cmd = 1'b0`（腿放下 = 蜷缩）✓

**结论**：✅ **完整实现**。默认状态就是腿蜷缩，轮子驱动。

---

### ⚠️ ② 四腿抬升过小石头 —— **能跑，但越障成功率低**

**触发**：视觉类别码 `0x04` → `low_obst` → 进 `S_LIFT` ✓

**动作序列**（`S_LIFT`）：

| 子阶段 | `lift_cmd` | 电机 | 退出条件 |
|---|---|---|---|
| `LP_UP` | **1**（抬腿） | **停** | `lift_done` |
| `LP_CROSS` | **1**（保持抬） | **慢速走**（`SPD_SLOW`） | `path_clear` 或 2 秒超时 |
| `LP_DOWN` | **0**（放腿） | **停** | `lift_done` |

**动作本身是对的** ✓：抬 → 走 → 放

#### 🔴 问题 1：`LP_CROSS` 会在**错误时机收腿**

```verilog
LP_CROSS: begin
    if (path_clear || t_cross >= CROSS_TMO_W) begin
        nphase = LP_DOWN;
    end
end
```

`path_clear` 的定义（`main_fsm.v`）：

```verilog
wire path_clear = dist_valid && (dist_mm >= DIST_CLEAR_MM);   // ≥ 800mm
```

**而 `dist_mm` 来自【前向 TOF】。**

**时间线：**

```
   车头靠近石头
        ↓
   [前向TOF] 读数变小
        ↓
   抬腿，慢速前进
        ↓
   车头越过石头 ──→ 前向TOF 读数突然变大 ──→ path_clear = 1
        ↓                                          ↓
        │                              此时【后轮还在石头前面/上面】！
        │                                          ↓
        └──────────────────────────────→ 收腿 LP_DOWN
                                                   ↓
                                    车身下降 → 石头磕到后部 / 后轮卡住
```

**结论**：**不是不能用，是"过小石头经常失败"** —— 因为收腿时机早了一个车身。

#### 🔴 问题 2：不装限位开关就**完全用不了**

```verilog
LP_UP: begin
    if (lift_done)                        nphase = LP_CROSS;
    else if (lift_fault || t_up >= 3秒)   nstate = S_ESTOP;   // ← 急停
end
```

**`lift_done` 来自限位开关。如果不装：**
- `lift_done` 永远为 0
- 每次进 `LP_UP` 都是 **3 秒后直接急停** ✗

**而 `LP_DOWN` 同理** —— 也需要 `lift_done` 才能回 `S_AUTO`。

**结论**：⚠️ **限位开关是必需件，不是可选项**（除非改代码支持"无反馈模式"）。

#### 🔴 问题 3：限位开关**极性反了**（第 4 节详述）

### ✅ ③ 大障碍绕行 —— **能实现**

**触发**（两个来源取或）：

```verilog
S_AUTO: if (obst_stop || vis_obst) nstate = S_AVOID;
```

| 来源 | 定义 | 覆盖场景 |
|---|---|---|
| `obst_stop` | `dist_mm < 200mm`（TOF） | 任何靠得近的东西 |
| `vis_obst` | 视觉类别码 `0x02`（保持 300ms） | 细杆、玻璃等 TOF 漏掉的 |

**避障动作**（`S_AVOID`）：

```verilog
S_AVOID: begin
    motor_en_r  = ~obst_stop;                    // 太近才停，否则继续走
    speed_scale = obst_stop ? SPD_STOP : SPD_SLOW;   // 慢速
    lift_cmd    = 1'b0;
end
```

**转向**：由 ARM 通过 UART 发 `steer` 值，`motion_decision` 转成左右轮差速 ✓

**退出条件**：

```verilog
S_AVOID: begin
    if (low_obst)                       nstate = S_LIFT;    // 绕行中发现矮障碍
    else if (path_clear && !vis_obst)   nstate = S_AUTO;    // 通畅且视觉清除
    else if (t_avoid >= 5秒)            nstate = S_ESTOP;   // 久困不脱 -> 急停
end
```

**结论**：✅ **完整实现**。
**依赖**：ARM 必须持续给 `steer`，否则车会减速但不转向。
**安全**：5 秒绕不过去会进急停 ✓

---

### ❌ ④ 两腿抬升跨台阶 —— **做不了**

**三个硬性阻塞：**

| # | 阻塞 | 说明 |
|---|---|---|
| **1** | **`lift_cmd` 只有 1 位** | `top.v`：`output wire lift_cmd`<br>前后腿**连在一起**，无法"前腿先抬、后腿再抬" |
| **2** | **`lift_phase` 只有 3 个阶段** | `LP_UP` / `LP_CROSS` / `LP_DOWN`<br>爬台阶需要 **6 个阶段**（前抬/前走/后抬/后走/都放） |
| **3** | **没有"台阶"类别码** | 视觉类别只有 `0x00~0x04`，**没有台阶**这个分类<br>目前无法触发（需要 B 在 ARM 侧新增）|

**结论**：❌ **完全做不了，需要改代码 + 改 ARM**。

**改动量估算**：
- `top.v`：`lift_cmd` → `[1:0]`，新增 `lift_pwm[1:0]`、`lift_lim_n[1:0]`
- `main_fsm.v`：`lift_phase` → `[2:0]`，新增 3 个子阶段
- `tb_main_fsm.v` / `tb_top_integration.v`：更新信号
- `verify_main_fsm_model.py`：同步更新
- **ARM（B）**：新增类别码 `0x05`

## 3. 发现的问题清单（**全部未修，等确认**）

| # | 问题 | 严重度 | 触发条件 | 后果 |
|---|---|---|---|---|
| **P1** | **限位开关极性反了** | 🔴 **高** | 一接上就触发 | 一进 `LP_UP` 就误判"已到位" |
| **P2** | **`lift_fault` 上拉误报** | 🔴 **高** | 一接上就触发 | 立刻进 `S_ESTOP` |
| **P3** | **`LP_CROSS` 提前收腿** | 🟠 中 | 每次过小石头 | 石头磕车身后部 |
| **P4** | **不装限位开关则完全不可用** | 🟠 中 | 不装限位 | 抬腿 3 秒后急停 |
| **P5** | **没有台阶类别码** | 🟠 中 | 遇到台阶 | 无法触发跨台阶 |
| **P6** | **`lift_cmd` 位宽不足** | 🟠 中 | 跨台阶需求 | 前后腿无法分开控制 |

### P1 / P2 详细说明

引脚表里现状：

```
lift_done ,D17,LVCMOS33,UP,,GPIO0_18   输入: 到位反馈
lift_fault,C17,LVCMOS33,UP,,GPIO0_19   输入: 故障
```

**`UP` = 上拉。** 而限位开关是**常开（NO）**触点：

| 实际状态 | 上拉后的引脚电平 | 代码判定（高有效） | 对不对 |
|---|---|---|---|
| 未按下（**未到位**） | **1** | `if (lift_done)` → **"已到位"** | ❌ **反了** |
| 按下（**到位**） | 0 | "未到位" | ❌ |

**`lift_fault` 同理**：
- 空闲（无故障）→ 上拉读 **1**
- 代码 `if (lift_fault)` → **误判故障** → 立刻 `S_ESTOP` ✗

**⚠️ 为什么仿真发现不了**：tb 里直接给 `lift_done` 赋理想值，绕过了"上拉 + 常开开关"这个物理现实。

**修法**：在 `servo_lift.v` 里做**极性转换 + 消抖**，`main_fsm` 保持 `if (lift_done)` 不变。
（`servo_lift.v` 已写好，**还没接进 `top.v`**。）

## 4. 三个方案在代码里的完整数据流

### ② 过小石头

```
ARM 视觉: 类别 0x04
   ↓ UART (AA 55 | VER | TYPE | LEN | DATA | BCC | 55 AA)
uart_frame → vision_rx → vision_class[7:0]
   ↓
main_fsm: low_obst = vision_valid && (vision_class == 0x04)
   ↓
S_AUTO --low_obst--> S_LIFT
   ↓
LP_UP  : lift_cmd=1, 电机停   --lift_done--> LP_CROSS
LP_CROSS: lift_cmd=1, 慢速走  --path_clear|超时--> LP_DOWN   ★问题P3
LP_DOWN : lift_cmd=0, 电机停  --lift_done--> S_AUTO
   ↓
servo_lift: lift_cmd → 50Hz 舵机 PWM → 腿
```

### ③ 绕行

```
TOF: dist_mm < 200  ─┐
                     ├─→ S_AVOID
ARM: 类别 0x02       ─┘
   ↓
S_AVOID: motor_en=1, SPD_SLOW, steer 由 ARM 给
   ↓
motion_decision: target[g] = base + (steer>>>4) × STEER_COEF[g]
   ↓
pwm_motor[0..3] → TB6612 → 左右轮差速 → 转向
   ↓
path_clear && !vis_obst --> S_AUTO
```

### ④ 跨台阶（**缺**）

```
需要但不存在：
  vision_class == 0x05        ← B 要新增
  lift_cmd[1:0]               ← 要扩位
  lift_phase: F_UP/F_CROSS/R_UP/R_CROSS/DOWN   ← 要新增阶段
```
