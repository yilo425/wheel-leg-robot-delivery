## 0. 先明确整车形态（**新理解，重要**）

```
        ┌─────────────────────┐
        │      车  身          │   ← FPGA 板 / ARM 板 / 电池
        └──┬──────────────┬───┘
          │              │
        ┌─┴─┐          ┌─┴─┐      ← 四条腿（可摆动/伸缩）
        │ 腿 │   ...    │ 腿 │
        └─┬─┘          └─┬─┘
          │              │
         (O)            (O)         ← ★ 轮子在腿【末端】
```

**关键结论：**
- **移动全靠轮子**，轮子在**腿末端**，随腿一起动
- **腿大部分时间蜷缩** → 车身贴近地面 → 就是普通轮式车
- **腿只负责把车身顶起来**（不是把轮子抬高！）→ 抬高离地间隙

**三种障碍策略：**

| 障碍 | 判定 | 动作 | 代码状态 |
|---|---|---|---|
| **小石头**（长度 < 整车） | 视觉 `0x04` | **四腿一起抬** → 开过去 | `S_LIFT`（现有） |
| **大障碍**（长度 ≫ 整车） | 视觉 `0x02` | 抬腿无用 → **绕行** | `S_AVOID`（现有） |
| **台阶/门槛** | 视觉 `0x05`（**待 B 新增**） | **前腿抬→走→后腿抬→走** | ❌ **待实现** |

## 2. 腿部分（★ 本项目最难的部分）

### 2.1 舵机 ×4

| 项 | 要求 | 说明 |
|---|---|---|
| 数量 | **4** | 每条腿 1 个 |
| 类型 | **180° 位置舵机** | ⚠️ **不要 360° 连续旋转型！**<br>代码发的是位置 PWM（0.5~2.5ms） |
| 扭矩 | **≥ 13 kg·cm** | 见下面扭矩估算 |
| 齿轮 | **金属齿** | 承重必须金属齿 |
| 供电 | **4.8-6V** | 独立供电，不能从 FPGA 板取电 |

**推荐型号**：`MG996R`（金属齿，13kg·cm，¥15-30）
**备选**：`DS3218`（20kg·cm 数字舵机，¥40-60）

**估价**：¥20-35 / 个　→　**¥80-140**

### 2.2 ★ 扭矩估算（C 必须自己复核）

```
整车估重        ≈ 1.5 kg（电池 0.25 + 板子 0.2 + 结构 0.6 + 电机轮子 0.45）
每条腿分担      ≈ 0.4 kg
连杆有效力臂    ≈ 3~5 cm
所需扭矩        ≈ 0.4 × 5 cm = 2.0 kg·cm

MG996R = 13 kg·cm  →  余量 6.5 倍  ✓ 够用
```

**但有余量不等于可以长期承重 —— 见 §2.4。**

### 2.3 ⚠️ 舵机电源（**这条最容易出事**）

| 项 | 要求 |
|---|---|
| **独立降压模块** | **5V / ≥5A**（DC-DC 可调降压） |
| 输入 | 接电池（12V） |
| 输出 | **只给舵机**，不走 FPGA 板 |
| **大电容** | **1000µF 以上**并在舵机电源上，吸收堵转冲击 |
| 线径 | **≥22AWG**，电源线短而粗 |

> **为什么必须独立供电**：
> MG996R 堵转电流 **2.5A**，4 个同时动可达 **10A**。
> 和 FPGA 共用一路 → 电压跌落 → **FPGA 复位**。
> **这是这类机器人最常见的"莫名其妙重启"原因。**

**估价**：¥15-25

### 2.4 ⚠️⚠️ 给 C 的机械设计硬约束

**舵机不能长期承重！**

腿"放下/蜷缩"是**默认状态，占 99% 的时间**。如果整车重量**一直压在舵机上**：
- 舵机会持续发热
- 会抖动（堵转电流大）
- 会缩短寿命甚至烧毁

**必须做：**
1. **腿到极限位置要有机械止挡**（金属/打印件顶住，让重量走结构不走舵机）
2. 或加**扭簧 / 气弹簧**分担静态负载
3. 或腿用**自锁机构**（蜗轮蜗杆 / 丝杆）

**这一条没做好的话，跑 10 分钟舵机就烫手了。**

### 2.5 限位开关 ×4

| 项 | 要求 |
|---|---|
| 数量 | **4**（前腿 1 + 后腿 1 + 备用 2） |

## 3. 感知部分

### 3.1 TOF 激光测距 ×2 ★建议买 2 个

| 项 | 要求 |
|---|---|
| 型号 | **VL53L0X**（I2C，2~200cm） |
| **数量** | **2** —— **前向 1 个 + 后向 1 个** |
| 接口 | **I2C**，接板上 I2C 排针（`SDA=M16`、`SCL=M13`） |
| 地址 | VL53L0X 默认地址相同，两个要用 I2C 多路复用或改地址 |

**为什么买 2 个（重要）：**

现有代码判断"越障完成"用的是**前向 TOF 距离变远**（`path_clear`）。
但小石头的定义是**长度小于整车** —— 车头过了石头时，**后轮还没过**。
**只有前向 TOF 会在错误的时机收腿，石头会磕到后部。**

**加一个后向 TOF → 前后都通畅才收腿** ✓

> 也可以不加，改用"时间判定"（我改代码即可）。但**有后向 TOF 更可靠**。

**估价**：¥15-30 / 个　→　**¥30-60**

## 5. ★ 电机标定（买回来后要做的）

代码里的满速参考值是：

```verilog
// rtl/top.v
parameter integer SPEED_WIN = 500_000;   // 测速窗口 = 10ms @50MHz
parameter integer VREF_FULL = 60;        // 满速目标计数/窗口
```

**标定公式**（`encoder_decode.v` 是 **4 倍频**解码）：

```
每轮一圈的计数 = PPR × 4 × 减速比

VREF_FULL = (目标转速RPM / 60) × (PPR × 4 × 减速比) × 窗口秒数
```

**例**（PPR=11，减速比 1:30，窗口 10ms）：

```
每圈计数 = 11 × 4 × 30 = 1320
VREF     = (RPM/60) × 1320 × 0.01 = RPM × 0.22
当前 VREF=60  →  对应 273 RPM  ✓ 合理
```

> **买回来后请把「减速比 + PPR」告诉我，我把 `VREF_FULL` 重新算准。**
> 这个值决定"满速档"实际跑多快。
