| 5 | 顺序 | 上面四步的**先后顺序**不能变 |

### ★ 已发现的设计冲突：一条 I2C 总线只能有一个 master

**现状**：✅ **已解决**（2026-10-15）。

原来 `tof_driver` **内部**例化了自己的 `i2c_master`，`imu_driver` 照抄同样的结构
→ 两者**各自驱动 `i2c_scl`/`i2c_sda`**，两个 master 同时说话，事务互相打断、
读回的数据是坏的，而且**不会报错**。

> `i2c_master.v` 头注释写着"TOF 和 MPU6050 共用一路 I2C，所以本模块只做通用搬运工"——
> 那句注释的意图是对的，但当时的接法没落实它。

**实际实现（和最初设想的"引脚级 mux"不一样，别照旧稿看）**：

```
     tof_driver ──┐ bus_req/bus_busy                 ┌── 各自的 i2c_master（保留）
                  ├──► i2c_bus_arb ──► bus_grant     │
     imu_driver ──┘                                  └──► scl/sda 直接**线与**到
                                                          i2c_scl / i2c_sda（板上）
```

1. **不需要 mux**：I2C 是**开漏**总线，两个驱动的 scl/sda 直接并到同一根线
   就是"线与"（任一拉低即为低），电气上本来就成立。
   ⚠️ 而"片内三态 mux"是**不能综合**的（FPGA 内部没有三态资源）——这条路走不通。
2. 真正缺的只有"同一时刻只允许一个 master 说话"：新增 `i2c_bus_arb`
   （轮询授权），每个驱动加 3 个端口 `bus_grant/bus_req/bus_busy`，
   把发车条件改成 `t_pending && !i2c_busy && bus_grant`。
3. ⚠️ **仲裁器释放 grant 的条件必须是"既没请求、也不忙"**
   （`!req && !busy`），**不能只看 `!busy`**：驱动"决定发车"的那一拍
   `t_pending` 还没清、`t_busy` 还没起（都是非阻塞赋值），只看 busy 会当场误释放
   → 另一个驱动立刻被授权 → **两个 master 同时上总线**。
   这个 bug 真发生了，是 `tb_top_i2c_share` 抓出来的（症状：MPU 寄存器里出现
   VL53L0X tuning 表的 0x44，两边初始化都跑不完）。
4. 板上收益：MPU6050 `0x68`、VL53L0X `0x29` 不冲突，可以并挂；
   **两块 VL53L0X 仍会冲突**（后向 TOF），得靠 `XSHUT` 改地址。

**验证**：`tb_top_i2c_share`（28 项）—— 两个真实从机模型挂同一条总线，
除了"两边都出数"，还有**交叉污染检查**：MPU 只写的 `0x19` 在 VL53L0X 模型里
必须仍是初值、VL53L0X 只写的 `0x4E` 在 MPU 模型里必须仍是初值。
从机模型也一并修成"**只有地址命中才 ACK / 才处理后续字节**"
（原来对任何地址都应答，单器件时看不出，挂一条总线上就会互相应答）。

## 六、环境备忘（踩过的坑）

| 坑 | 说明 |
|---|---|
| **ModelSim 不能用中文路径** | 工作库必须在纯 ASCII 路径。已迁到 `D:\dsh-ws\robot_project\.simlib\work` |
| **★ ModelSim 批处理输出被"管道"捕获 + 中文用户名 → `vsimk` 退出码 7** | 2026-10-15 踩到：把 `vsim -c -do run_sim.do` 的输出用 PowerShell 管道接走（`\| Select-String ...`）时，ModelSim 会把 stdout 溢出内容写到 `%TEMP%` 的 `VSOUTxxxx` 文件；本机 `%TEMP% = C:\Users\忆洛\AppData\Local\Temp`，中文用户名被 ANSI 化成 `????` → `Error while reopening stdout stream! ... filename is invalid on this platform` → **`** Fatal: vsimk is exiting with code 7`**，跑一半就断（症状：最后几条 tb 的结果文件是空的或没生成，看起来像 tb 崩了，其实和 tb 无关）。**对策**：① 把 `TEMP`/`TMP` 指到纯 ASCII 目录再跑（`set TEMP=D:\dsh-ws\_tmp`）；② 输出用**文件重定向**（`cmd /c "... > sim_full.log 2>&1"`）而不是管道。输出量小时不会触发，所以很容易误判成"某条 tb 有问题" |
| **`vsim` 报 `Error loading design` 时** | **只有 `vopt` 会报真实错误** |
| **`vsim` 要加 `-voptargs="+acc"`** | 否则内存引用（`dut.xxx`）被优化掉 |
| **`sim/*.do` 是生成物** | 别在两个仓库间 robocopy 同步，会覆盖成旧版。**加了新文件要重跑 `emit_dofiles.ps1`**（见 §七） |
| **`.ps1` 必须有 UTF-8 BOM** | 丢了 PowerShell 按 GBK 读中文注释 → 解析失败。**用 AI/编辑器改 `.ps1` 后特别容易丢 BOM**（很多工具写回的是不带 BOM 的 UTF-8）→ 改完必须确认头三个字节是 `EF BB BF` |
| **PowerShell 变量大小写不敏感** | `$r` 会覆盖 `$R` —— 本项目踩过两次 |
| **`parameter` 不能位选** | Verilog-2001 限制，先转定宽 `localparam [31:0]` |
| **`.sdc`/`.tcl` 必须纯 ASCII** | Gowin 按 GBK 读 |
| **ModelSim task 端口 `[255:0]` 只装 32 字节** | 检查名太长会丢开头的字（本工程已加宽到 `[1023:0]`） |
| **测试里"等毫秒"要用 `wait_ms` task** | 1ms = 50000 拍，`repeat(60)` 差三个数量级 |
| **单拍脉冲只能"数"，不能"采"** | `dist_valid`/`dist_err` 是单拍脉冲；而且 `tof_driver` 用非阻塞赋值更新它们，tb 在同一拍读到的是**上一拍**的值 —— 所以要让监视块计数，断言盯计数，别直接采那根线 |
| **本会话的沙箱写权限** | 实测 shell 只能写工作区**根**目录，`rtl/`/`sim/`/`build/` 等子目录写入被拒（`POLICY_DENIED`）。跑 ModelSim / `gen_cst.py` / Gowin 综合要单独申请提权（或把会话切到完全权限）。**文件编辑走原生工具不受影响** —— 但正因为这样，`.ps1` 的 BOM 就是这么丢的 |
| **★ Gowin 原语库的版本必须与综合器一致** | 2026-10-15 发现：ModelSim 里的 `gw5a` 库是 **V1.9.11** 的 `prim_sim.v` 建的，而综合用 **V1.9.12** —— 仿真模型和综合器不是一个版本。判法：`vdir -lib D:/modeltech64_2020.4/gw5a \| findstr "MODULE DQS"`，**有输出 = 旧版**（V1.9.12 已把 `DQS` 移出 `prim_sim.v`），无输出 = V1.9.12（132 个模块）。详见 `doc/toolchain_gowin_modelsim.md` 的「2026-10-15 更新」 |
| **★ 多版本 Gowin 共存时别靠"第一个找到的"** | 本机同时装着 V1.9.11 和 V1.9.12，目录枚举顺序不保证。已让 `setup_gowin_modelsim.ps1` **按版本号取最新**（否则又会拿旧版建库） |
| **★ `toolchain.local.ps1` 必须存在** | 它在 `.gitignore` 里（每台机器一份）。**不建它**：`emit_dofiles.ps1` 走内置默认值，会把 work 库写到仓库外的 `D:\gowin_lib\work`，而工程一直用 `.simlib\work` —— 库一分家，换机器就找不到，且不报错。已按本机建好 |
