## 4. ⚠️ 需要外部信息才能继续设计的部分

> **这一节是本次交接的重点。** 下面每一项都写清了"缺什么信息"和"缺了会怎样"。

### 4.1 需要【机械组】提供 —— 阻塞 4 个模块

#### (1) 底盘驱动形式 ★最高优先级

**为什么关键**：`motion_decision` 的转向逻辑完全依赖它。

| 需要回答 | 影响 |
|---|---|
| 差速？麦克纳姆？四轮独立？ | `motion_decision` 的 4 个 `STEER_COEF` 系数取值 |
| 轮径（mm）？ | 把"编码器计数/窗口"换算成 mm/s（**上报和路径规划都要用**） |
| 轮距 / 轴距（mm）？ | 转向时的差速比例 |
| 4 个轮子的**编号与位置对应关系**（哪个是左前？） | `top.v` 里通道映射、`duty0..3` 的实际含义 |
| 减速比？ | 编码器计数 → 实际转速的换算 |

**现状**：默认按"左两轮 +1、右两轮 −1"的差速配置写的。
换底盘**只需改参数、不用改逻辑**（这是刻意设计的），但必须知道改什么。

#### (2) 升降腿舵机

| 需要回答 | 影响 |
|---|---|
| 舵机型号、角度范围 | `servo_lift.v` 的脉宽标定（500~2500us？） |
| **是否有位置反馈？** | ⚠️ **`main_fsm` 的 `lift_done` 信号从哪来？** |
| 如果没有位置反馈 | 只能用"时间估计"或加限位开关 —— **这是个必须先定的方案** |
| 抬腿/放腿的动作时间 | `LIFT_TIMEOUT_MS` 阈值 |

> ⚠️ **`lift_done` 的来源是个真实的悬空问题。**
> `main_fsm` 已经预留了这个输入端口并在等它，但没有传感器就没有这个信号。
> 三个可选方案（需机械组确认）：
> 1. 舵机带位置回读 → 直接接
> 2. 加限位开关 → `main_fsm` 直接用
> 3. 都没有 → 用固定延时"假装到位"（最差方案，但能跑通演示）

#### (3) 机械安装与走线

| 需要回答 | 影响 |
|---|---|
| FPGA 板装在哪个位置 | 排线长度、是否需要差分/缓冲 |
| 传感器（TOF/IMU）朝哪个方向 | 安装坐标 → 距离/角度符号约定 |
| 急停按钮装在哪、怎么接 | **见 §4.4 安全性问题** |

### 4.2 需要【电控/机械】提供 —— 阻塞电机驱动与上板

#### (4) 电机与驱动器

| 需要回答 | 影响 |
|---|---|
| 电机型号、额定电压/电流、堵转电流 | 驱动板选型、电源容量 |
| 有刷 / 无刷 / 步进？ | 驱动方式完全不同 |
| 驱动器是**板载 H 桥**还是**外购模块**？ | 接口定义 |
| 驱动器接口形式：`PWM + DIR`？还是别的？ | `pwm_motor.v` 是否够用 |
| 驱动器**逻辑电平**：3.3V 还是 5V？ | **FPGA 是 3.3V，5V 输入需要电平转换** |
| 使能脚极性（高有效/低有效） | `motor_enable` 是否需要取反 |
| 期望 PWM 频率 | `PWM_FREQ_HZ` 参数（现默认 20kHz） |

#### (5) 编码器

| 需要回答 | 影响 |
|---|---|
| 型号、**线数（PPR）** | 测速窗口 `SPEED_WIN` 与 `VREF` 标定 |
| 输出类型：单端 / **差分**（A+/A-）？ | 差分需要额外接收芯片 |
| 输出电平、供电电压 | 电平转换 |
| **每轮一个**还是**每侧一个**？ | `encoder_decode` 例化几路 |
| 是否与电机同轴（在减速前还是后） | 计数换算 |

#### (6) FPGA 板与实际引脚

| 需要回答 | 影响 |
|---|---|
| ~~板子型号确认~~ | ✅ 已确认：**GW5AT-138**（`GW5AT-LV138PG484AC1/I0`）<br>⚠️ 是 GW5**AT** 不是 GW5**AST**（ID 差一位，见 `doc/board_pinout.md` 第 2 节）|
| 板子原理图 / 引脚分配表 | ⚠️ **`constraints/top.cst` 里现在全是占位值 `PIN_xx`** |
| 板上已占用的引脚（LED/按键/晶振/UART） | 避免冲突 |
| 晶振频率（50MHz？） | `CLK_FREQ_HZ` 参数 |

### 4.3 需要【ARM 组】确认

| 需要回答 | 影响 |
|---|---|
| **视觉类别码定义** | `main_fsm` 的 `VIS_LOW_OBST` 现在只定了 `0x04`，其余类别待定 |
| ARM 能否提供 `goal_reached`（到达终点判定） | `main_fsm` 的 `AUTO → GOAL` 转移 |
| 转向指令由谁产生、什么格式 | `motion_decision` 的 `steer` 端口现在给 0（走直线） |
| UART 参数确认 | 已在 `uart_frame_protocol.md` 定义，需 ARM 侧对齐 |
| ARM 是否也需要急停通路 | 两条独立的急停通路更安全 |

### 4.4 ⚠️ 安全性问题（必须有人拍板）

| 问题 | 说明 |
|---|---|
| **急停是硬件断电还是信号级？** | 现在的 `estop` 是**信号级**（进 FPGA 引脚）。<br>如果 FPGA 死机/程序跑飞，信号级急停**可能失效**。 |
| **强烈建议** | 急停按钮**直接串在电机电源回路**上（硬件断电），FPGA 的 `estop` 作为**第二重**保护。<br>这是竞赛答辩时的加分点，也是真正的安全要求。 |
| 电池规格 | 电压/容量 → 影响驱动板与电源方案 |
| **共地方案** | FPGA / 电机 / ARM / 电池**必须共地**，否则串口和编码器会乱 |
