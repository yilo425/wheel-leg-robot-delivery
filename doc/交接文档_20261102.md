# 一、项目一句话介绍

**一台四足四轮的运动机器人**：四条腿用舵机做「站立高度调节」，四个轮子用直流减速电机做「全向移动」，主控用 **FPGA + K230 双芯片**，手机连 WiFi 就能遥控。

# 二、系统架构

```
        手机浏览器（WiFi）
                ↓ HTTP
    ┌───────────────────────┐
    │   K230 庐山派 Lite    │  ← MicroPython / CanMV
    │   · HTTP 服务器       │
    │   · 网页控制界面      │
    │   · 视觉（预留）      │
    └───────────┬───────────┘
                │ UART 115200（3 根线）
                ↓
    ┌───────────────────────┐
    │  FPGA GW5AT-138       │  ← Verilog，50MHz
    │   · 遥控帧解析        │
    │   · 运动决策（差速）  │
    │   · 速度闭环/开环     │
    │   · 电机 PWM 生成     │
    │   · 舵机 I²C 控制     │
    │   · 堵转保护/软启动   │
    └────┬────────────┬─────┘
         │            │
    ┌────↓────┐  ┌────↓──────┐
    │ TB6612  │  │ PCA9685   │
    │ 4 路驱动│  │ 16 路 PWM │
    └────┬────┘  └────┬──────┘
         ↓            ↓
    4× MG310     4× MG996R
    （轮子）      （腿）
```

## 为什么用双芯片

| 芯片 | 负责 | 优势 |
|---|---|---|
| **FPGA** | 实时控制（PWM、编码器、保护） | **微秒级确定性**，不卡顿 |
| **K230** | 网络、界面、视觉 | Python 开发快，能跑 AI |

**分工原则**：实时的事给 FPGA，复杂的事给 K230 ✓

# 四、软件功能

## 4.1 已实现功能

| # | 功能 | 实现方式 |
|---|---|---|
| 1 | **手机 WiFi 遥控** | K230 建热点 `RobotRC`，HTTP 服务器 8080 端口 |
| 2 | **零 JS 控制网页** | 纯 HTML + 服务端渲染（手机浏览器不一定执行 JS）|
| 3 | **前进/后退/左转/右转/停止** | 差速转向 |
| 4 | **连续调速** | 0~100% 线性，可选 40% / 80% |
| 5 | **站立高度升降** | 4 舵机同步，慢速 2 秒（限流保护）|
| 6 | **限位保护** | 到位后继续按键无反应（pos 饱和）|
| 7 | **堵转保护** | 占空比大 + 编码器不动 → 断电冷却 |
| 8 | **软启动斜坡** | 占空比每毫秒最多涨 8/128，约 16ms 到满 |
| 9 | **遥控看门狗** | 500ms 收不到帧就自动停车 |
| 10 | **遥测上报** | FPGA 10Hz 上报状态/距离给 K230 |

## 4.2 通信协议

```
帧格式：AA 55 | VER | TYPE | LEN(2B) | DATA | BCC | 55 AA
BCC = XOR(VER, TYPE, LEN_H, LEN_L, DATA...)

上行（K230 → FPGA）：
  0x02 VISION_RESULT  视觉结果
  0x04 CONFIG         配置（vref/限速/站立高度/手动模式）
  0x05 RC_CMD         遥控指令（steer, speed, seq）

下行（FPGA → K230）：
  0x10 TELEMETRY      遥测（10Hz，13 字节）
```

**RC_CMD 字段**：
```
steer : int8   -100..100（正 = 右转）
speed : uint8  bit7 = 后退标志，bit6:0 = 0..100%
seq   : uint8  自增序号
```

# 五、关键技术点（PPT 可重点讲）

## 5.1 双芯片异构架构

```
FPGA 做实时（微秒级）
K230 做网络/AI（Python 生态）
    ↓
既保证了运动控制的确定性，又保留了上层开发的灵活性
```

## 5.2 差速转向的按比例偏置

```verilog
bias = base × steer / 100
target = base ± bias
```

```
steer = 100%  →  内侧轮 = 0，外侧轮 = 2×base
              →  绕内侧轮原地转，最小半径 R = W/2 = 115mm
steer = 0     →  直行
```

**相比"固定偏置"的优势**：转向幅度和车速联动，慢速不会转过头，快速不会转不动 ✓

## 5.3 舵机"慢速限流"升降

```
102 个计数（45°），每 20ms 走 1 个 → 约 2 秒走完
    ↓
舵机启动电流是运行电流的 3~5 倍
慢速转动 ⇒ 峰值电流小 ⇒ 不烧舵机、不拉垮电源 ✓
```

## 5.4 编码器闭环 + 开环兜底

```
正常：duty = (目标速度 - 编码器反馈) >> KP_SHIFT   ← 闭环
异常：编码器断线/极性反 → 自动切开环 duty = ±base ← 兜底
    ↓
防止"编码器坏了机器人自己跑到满速"
```

## 5.5 多层安全保护

| 层级 | 保护 |
|---|---|
| 遥控层 | 500ms 看门狗 |
| 决策层 | 急停优先级最高 |
| 驱动层 | 堵转检测 + 软启动 |
| 硬件层 | 3S 电池 + 5A 保险丝 |

# 七、踩过的坑（很好的"工程实践"素材）

| # | 问题 | 根因 | 解决 |
|---|---|---|---|
| **1** | 网页"一直断开闪烁" | HTTP 热路径每次请求写 2~4 次 SD 卡日志，单请求 100~200ms，浏览器 100ms 轮询必然超时 | 关掉热路径日志，只保留开关 |
| **2** | 点按钮"网页无法打开" | 参数字典漏了键 → `KeyError` → 连接被掐断 | 去掉白名单，全部用 `.get()` |
| **3** | 网页只显示一半 | MicroPython 的 `socket.send()` 可能只发一部分，剩余被丢弃 | 改成循环发送直到发完 |
| **4** | 所有网址一片空白 | 文件是 **CRLF 换行**，MicroPython 在跨行表达式处报 SyntaxError → 模块导入失败 | 强制 LF 换行（加了 `.gitattributes`）|
| **5** | **电机全不转** | **STBY（待机）脚没接** → 驱动芯片一直待机 | 接 FPGA 的 E16 |
| **6** | 某一路电机永远高速 | 该路**编码器 A/B 接反** → 闭环变正反馈 → 积分跑飞 | 改开环，或修正编码器极性 |
| **7** | 驱动板单通道烧毁 | ①带电接线短路 ②电机堵转（安装螺丝压歪电机轴）| 加保险丝 + 断电接线 + 装前手转确认 |
| **8** | 每次复位行为都变 | 固件只在 SRAM，断电/复位回旧 Flash | 固化 Flash |

## 最值得讲的一条

> **"电机一转不转"这个问题，查了整整两天。**
> 最后发现是 **STBY 使能脚没接** —— 一个信号线的问题，
> 却表现为"代码、驱动板、电机全都不对"。
> **教训：排障要先确认「使能」和「供电」，再查逻辑。**

## 13.4 供电

```
3S 电池 12.6V
 ├─ 5A 保险丝 → 驱动板 Vin+（电机）

 ├─ UBEC   → 5.16V → PCA9685 V+（舵机）
```

## 13.5 上电顺序

```
FPGA 先上电 → 看 D0/D3 亮 → UBEC 等 1~2 分钟稳定 → 给舵机供电 → K230 上电
```
